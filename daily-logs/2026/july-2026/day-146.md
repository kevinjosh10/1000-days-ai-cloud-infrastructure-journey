# Day 146 – Terraform Provisioners & Import

**Date:** 25 July 2026
**Duration:** ~3 Hours
**Focus:** Bringing legacy infrastructure under IaC control (`terraform import`), forcing recreation (`-replace`), and the anti-patterns of `local-exec` and `remote-exec` provisioners.

---

## 🎯 Objective

Learn how to integrate pre-existing, manually clicked cloud resources into a strict declarative Terraform state, and understand the architectural dangers of imperative provisioners.

Learn:

- The necessity of `terraform import` in legacy environments
- Reverse-engineering HCL blocks to match live AWS reality
- Achieving the 'Zero-Diff' `terraform plan` on imported resources
- The `local-exec` and `remote-exec` provisioners
- Why Provisioners break the Terraform declarative lifecycle
- Tainted state and failure handling in imperative scripts
- The `terraform apply -replace=RESOURCE` command (replacing `taint`)

Practice:

- Mastering The necessity of `terraform import` in legacy environments through direct terminal application
- Mastering Reverse-engineering HCL blocks to match live AWS reality through direct terminal application
- Mastering Achieving the 'Zero-Diff' `terraform plan` on imported resources through direct terminal application
- Mastering The `local-exec` and `remote-exec` provisioners through direct terminal application
- Mastering Why Provisioners break the Terraform declarative lifecycle through direct terminal application
- Mastering Tainted state and failure handling in imperative scripts through direct terminal application
- Mastering The `terraform apply -replace=RESOURCE` command (replacing `taint`) through direct terminal application
- Manually provisioning an S3 bucket via the AWS Web Console (ClickOps)
- Forcing the Terraform state file to adopt the rogue S3 bucket
- Iteratively modifying `main.tf` until the state perfectly aligns with reality
