# Day 151 – Terraform Workspaces

**Date:** 30 July 2026
**Duration:** ~3 Hours
**Focus:** State File Isolation, `terraform.workspace` Interpolation, and the Architectural Limitations of Workspace-Based Routing.

---

## 🎯 Objective

Master the use of Terraform Workspaces for managing logically distinct environments within a single codebase, while critically evaluating when to use workspaces versus physical directory separation.

Learn:

- The mechanics of Terraform Workspaces (`new`, `select`, `list`, `show`)
- How Terraform automatically isolates state files using the `env:/` S3 prefix
- Dynamic infrastructure sizing using the `terraform.workspace` reserved variable
- Conditional tagging logic based on the active workspace
- The 'Single Backend' limitation of workspace architectures
- HashiCorp's official stance on Workspaces vs Directory Separation
- Managing blast radiuses within a single codebase

Practice:

- Testing The mechanics of Terraform Workspaces (`new`, `select`, `list`, `show`) in the terminal
- Testing How Terraform automatically isolates state files using the `env:/` S3 prefix in the terminal
- Testing Dynamic infrastructure sizing using the `terraform.workspace` reserved variable in the terminal
- Testing Conditional tagging logic based on the active workspace in the terminal
- Testing The 'Single Backend' limitation of workspace architectures in the terminal
- Testing HashiCorp's official stance on Workspaces vs Directory Separation in the terminal
- Testing Managing blast radiuses within a single codebase in the terminal
- Creating a `staging` workspace and provisioning an isolated VPC
- Dynamically naming AWS resources by interpolating `${terraform.workspace}` into the HCL tags
- Switching to a `prod` workspace and verifying state segregation
- Introspecting the remote Amazon S3 backend to observe the physical `env:/` folder structure
