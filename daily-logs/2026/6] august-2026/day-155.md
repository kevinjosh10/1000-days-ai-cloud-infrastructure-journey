# Day 155: Advanced Data Sources & Dynamic Configuration

**Date:** August 3, 2026
**Focus:** Terraform Data Sources (AWS AZs, Caller Identity, SSM Parameter Store)

## Activities
* **Dynamic Availability Zones:** Replaced hardcoded `availability_zones` in the VPC module with the `data "aws_availability_zones"` data source. This automatically fetches the available AZs in the current region, making the module instantly portable to other regions without changing input variables.
* **AWS Context Data Sources:** Explored `data "aws_caller_identity"`, `data "aws_region"`, and `data "aws_partition"`. These are critical for dynamically building ARN strings (e.g., `arn:${data.aws_partition.current.partition}:s3:::my-bucket`) so code doesn't break across commercial, GovCloud, or China partitions.
* **SSM Parameter Store Secrets:** Migrated the `vpc_cidr` variable to instead read directly from an AWS Systems Manager Parameter Store via `data "aws_ssm_parameter" "vpc_cidr"`. This shifts configuration management out of the code repository and into the cloud provider, a massive step up in security and centralization for enterprise architectures.
* **Self-Documenting Data Lookups:** Explored fetching resources dynamically by tags (e.g., `data "aws_vpc"` by `tags = { Name = "production" }`) rather than relying on hardcoded `vpc-xxxxxx` IDs, ensuring environments don't break when underlying resources are rebuilt.

## Refactoring Project 1
* Successfully refactored `projects/terraform/aws-3tier-architecture/modules/vpc`.
* Removed `vpc_cidr` and `availability_zones` from `variables.tf`.
* Updated `main.tf` to inject data sources for AZ arrays and SSM CIDR values.
* Updated `environments/prod/main.tf` to call the refactored module cleanly.

## Key Takeaways
Data sources are the bridge between Terraform's local state and the dynamic reality of the cloud. By replacing static `variable` inputs with dynamic `data` lookups, modules become infinitely more portable, resilient to underlying cloud changes, and secure (in the case of fetching secrets from SSM).
