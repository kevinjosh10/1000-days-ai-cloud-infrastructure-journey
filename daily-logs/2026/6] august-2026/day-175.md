## 3. The CI/CD Pipeline (GitHub Actions)

Running `docker compose up` locally is great, but production requires automation. I built a GitHub Actions pipeline that completely automates my delivery:
1. **Linting:** Scans the Dockerfile using `hadolint` to enforce best practices.
2. **Build:** Builds the image.
3. **Security Gate:** Runs Trivy. The pipeline *fails immediately* if a `CRITICAL` vulnerability is found.
4. **Push:** Tags the image with the unique Git SHA (never `latest`) and pushes it to Amazon ECR.
5. **GitOps Prep:** A script automatically updates my future Kubernetes deployment manifest with the newly generated Git SHA tag.

## 4. Kubernetes Preview: The Next Frontier

With Docker mastered, I spent the afternoon studying the core Kubernetes (K8s) primitives I will be working with next week:
* **Pods:** The atomic unit of K8s; a wrapper around containers sharing a network namespace.
* **Deployments:** The controller that ensures the right number of Pods are always running (Self-Healing & Horizontal Scaling).
* **Services:** The abstract way to expose an application running on a set of Pods (ClusterIP for internal, NodePort/LoadBalancer for external).
* **ConfigMaps & Secrets:** Decoupling configuration and sensitive data from the immutable container image.

## 5. Architectural Thinking: Compose vs Kubernetes

To prove I understand the *why* and not just the *how*, I wrote an architectural comparison: **"Docker Compose vs Kubernetes — When to Use Each"**.
* **Docker Compose:** Perfect for local development, CI/CD testing environments, and single-node side-projects. It is fundamentally limited by the resources of a single machine.
* **Kubernetes:** Necessary for production systems that require high availability, multi-node scaling, zero-downtime rolling updates, and self-healing across a massive fleet of servers (like AWS EKS).

## 🧠 The 5 things I can confidently explain today

If asked in an interview, I can now articulate:

1. **What does a modern container CI/CD pipeline look like?**
   > Linting (`hadolint`) ➡️ Build ➡️ Vulnerability Scan (`Trivy`) ➡️ Tag with Git SHA ➡️ Push to ECR ➡️ Update K8s Manifest.
2. **Why do we tag images with a Git SHA instead of `latest`?**
   > To enforce absolute immutability and traceability. If a deployment fails, I know exactly which git commit caused it, and rolling back is instant.
3. **How do you handle startup race conditions in a microservices stack?**
   > By combining `HEALTHCHECK` on the database container with `depends_on: db: condition: service_healthy` on the API container.
4. **What are the primary K8s components?**
   > Pods (compute), Deployments (scaling/healing), Services (networking/load balancing), and ConfigMaps/Secrets (configuration).
5. **When should you migrate from Docker Compose to Kubernetes?**
   > When your application's availability and scaling requirements exceed the capacity or reliability of a single host machine.
