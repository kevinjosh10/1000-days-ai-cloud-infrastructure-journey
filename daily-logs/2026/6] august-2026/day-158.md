# Day 158 – Policy as Code — OPA & Sentinel Intro

**Date:** 06 August 2026

## 🎯 Objective

Understand how to shift from manual compliance documentation to automated, machine-enforced Policy as Code. 

Learn how to write deterministic policies that scan Terraform execution plans and automatically block insecure, untagged, or non-compliant infrastructure from ever reaching production.

---

## ✅ What I Completed

### 1️⃣ Understood Policy as Code

Learned why traditional compliance fails at enterprise scale.

Learned:
- Written documentation ("All S3 buckets must be encrypted") is frequently ignored or forgotten
- Human code reviews are prone to error and exhaustion
- Policy as Code solves this by treating compliance rules as executable code that runs in the CI/CD pipeline

Understood:
- Automated governance is the only way to scale security across hundreds of developers safely
- The pipeline becomes the ruthless enforcer of company standards

---

### 2️⃣ Learned Open Policy Agent (OPA) & Rego

Studied OPA, the industry-standard open-source policy engine.

Learned:
- Installed OPA using Homebrew (`brew install opa`)
- OPA uses a highly specialized query language called **Rego**
- Wrote a Rego `deny` block that scans for `aws_s3_bucket` resources
- Programmatically enforced that the `server_side_encryption_configuration` cannot be `null`

Understood:
- Rego allows you to write strict mathematical logic against infrastructure data
- OPA is universal; it works for Terraform, Kubernetes, and API Gateways

---

### 3️⃣ Used Conftest for Terraform Plan Validation

Practiced applying OPA policies directly to Terraform infrastructure.

Workflow studied:
1. `terraform plan -out=plan.out` (Generate the infrastructure execution plan)
2. `terraform show -json plan.out > plan.json` (Convert the binary plan into machine-readable JSON)
3. `conftest test plan.json` (Feed the JSON into Conftest to validate against the `.rego` policies)

Understood:
- Conftest acts as the crucial bridge between Terraform JSON outputs and OPA evaluation
- It returns standard exit codes (`0` for pass, non-zero for fail), making it perfect for automation

---

### 4️⃣ Explored HashiCorp Sentinel

Studied the native alternative to OPA used within Terraform Cloud and Enterprise.

Learned:
- Sentinel is HashiCorp's proprietary policy engine
- It uses a custom language that reads more like plain English than Rego
- Studied a rule enforcing that `all tfplan.resource_changes` of type `aws_instance` must contain an `Environment` tag
- Explored Sentinel's enforcement levels (e.g., "Hard Mandatory" physically blocks deployments)

Understood:
- If a company pays for Terraform Cloud, they likely use Sentinel
- If they use open-source Terraform, they use OPA/Conftest

---

### 5️⃣ Designed Automated CI/CD Governance

Practiced integrating policy enforcement directly into GitHub Actions.

Learned:
- CI/CD pipelines must be configured to run Conftest immediately after `terraform plan`
- If Conftest detects a violation (like an unencrypted bucket), it fails the pipeline step
- The GitHub Pull Request is instantly blocked with a red ❌, disabling the merge button

Understood:
- This creates a "Shift Left" security posture
- Developers get instant, automated feedback on security mistakes before human reviewers even look at the code
