## ✅ What I Completed

### 1️⃣ Deconstructed Docker Architecture

Studied how Docker actually executes under the hood.

Learned:
- **Docker Daemon (`dockerd`):** The persistent background service running on the host OS that builds, runs, and manages containers.
- **Docker CLI:** The `docker` terminal command. It is merely a client that sends REST API requests to the Daemon.
- **`containerd`:** The low-level industry-standard runtime that physically executes the container processes.
- **Docker Hub:** The public, centralized registry for downloading official base images.

Understood:
- Docker is not a single binary; it is a distributed client-server model that can be operated locally or remotely.

---

### 2️⃣ Mastered the Core Vocabulary

Studied the fundamental difference between states of software in Docker.

Learned:
- **Image:** A read-only, immutable template containing the OS, runtime, libraries, and application code. (Equivalent to an AWS AMI).
- **Container:** A running, isolated instance of an Image. It has its own CPU, RAM, and network space. (Equivalent to a running EC2 instance).
- **Layer:** Images are built using stacked layers. If you change one line of application code, Docker only rebuilds that specific top layer while caching the OS layers below it, making builds incredibly fast.

Understood:
- You do not "modify" running containers. If code changes, you build a new Image and spin up a new Container.

---

### 3️⃣ Executed Essential Lifecycle Commands

Practiced the daily-driver commands used by Cloud Engineers.

Commands mastered:
- `docker pull nginx`: Downloads the image from Docker Hub to the local hard drive.
- `docker images`: Lists all locally cached images and their file sizes.
- `docker run nginx`: Spins up a new container from the image.
- `docker ps`: Lists only currently active/running containers.
- `docker ps -a`: Lists *all* containers, including those that have crashed or gracefully exited.
- `docker stop <id>`: Sends a SIGTERM to shut down the container gracefully.
- `docker rm <id>`: Deletes the stopped container instance.
- `docker rmi <id>`: Deletes the underlying image to free up disk space.

---

### 4️⃣ Learned the Magic Flags of `docker run`

Studied how to configure a container's relationship with the host machine.

Flags mastered:
- `-d` (Detached): Runs the container in the background, freeing up the terminal.
- `-p 8080:80` (Port Mapping): Maps port `8080` on the laptop (Host) to port `80` inside the Container. Crucial for web traffic.
- `--name web01`: Assigns a static, human-readable name rather than a random hash (e.g., `jovial_einstein`).
- `-e DB_PASS=secret`: Injects Environment Variables securely into the container at runtime.
- `--rm`: Automatically deletes the container the exact second it stops, keeping the host system clean of dead containers.

---

### 5️⃣ Practiced Interactive Debugging

Mastered the most critical command for debugging containerized applications.

Workflow practiced:
1. Ran a detached Ubuntu container: `docker run -d --name my-ubuntu ubuntu sleep infinity`
2. Used the **execute** command to drop a shell into the running container: `docker exec -it my-ubuntu bash`
3. Explored the isolated Linux filesystem from the inside (`ls`, `cat /etc/os-release`).
4. Exited the shell and cleaned up the environment.

Understood:
- `docker exec -it` is the Docker equivalent of SSHing into a server. It provides an interactive TTY (`-it`) session straight into the isolated process.
