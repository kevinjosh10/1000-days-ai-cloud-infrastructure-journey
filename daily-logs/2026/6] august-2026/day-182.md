## 1. The CKA Speed Toolkit (Aliases)

The CKA exam is open-book, but it is brutally time-pressured. Typing `kubectl` 500 times is a waste of time. I set up the mandatory exam environment shortcuts:

```bash
alias k=kubectl
echo 'source <(kubectl completion bash)' >> ~/.bashrc
echo 'complete -F __start_kubectl k' >> ~/.bashrc
source ~/.bashrc
```
Now, I can type `k get po` and hit `TAB` to instantly auto-complete pod names. This simple trick easily saves 15 minutes over a two-hour exam.

## 3. The Debugging Tunnel: `port-forward`

I learned a massive security and debugging trick. If I have a database pod running internally on port `5432`, I do *not* need to create a NodePort service to access it from my laptop (which is a security risk).

Instead, I can open a secure, temporary SSH-like tunnel directly to the Pod:
```bash
k port-forward pod/db-pod 5432:5432
```
This binds my laptop's local `5432` directly to the Pod's `5432`. I can use pgAdmin on my laptop to query the production database securely, and the moment I hit `CTRL+C`, the tunnel collapses.

## 4. Live Cluster Telemetry: `kubectl top`

To see actual CPU and Memory usage, I enabled the metrics-server on my local cluster:
```bash
minikube addons enable metrics-server
```
Then I ran:
* `k top nodes` (To see if my EC2 instances are exhausted)
* `k top pods` (To find out which specific container is devouring RAM)

This is the Kubernetes equivalent of `docker stats` and is crucial for right-sizing limits and requests.

## 5. Week 26 Capstone: 3-Tier Architecture

To prove I've mastered Week 26, I wrote the YAML manifests from scratch and deployed a complete architecture to Minikube:
1. **Frontend:** Deployment (3 Replicas, Nginx) + LoadBalancer Service
2. **Backend:** Deployment (2 Replicas, Flask API) + ClusterIP Service
3. **Database:** Pod (PostgreSQL) + ClusterIP Service

### The Architecture:

```text
       [Laptop Browser]
              │
              ▼
    (LoadBalancer Service)
      frontend-service
              │
       ┌──────┼──────┐
       ▼      ▼      ▼
    [FE]   [FE]   [FE] (Frontend Pods - Nginx)
       │      │      │
       └──────┼──────┘
              ▼
      (ClusterIP Service)
        backend-service
              │
          ┌───┴───┐
          ▼       ▼
        [BE]    [BE] (Backend Pods - Flask)
          │       │
          └───┬───┘
              ▼
      (ClusterIP Service)
          db-service
              │
              ▼
            [DB] (Database Pod - Postgres)
```

I applied it all with `k apply -f k8s/`, watched the pods spin up, and tested the end-to-end flow using `minikube service frontend-service`.

## 🧠 The 5 things I can confidently explain today

If asked in an interview, I can now articulate:

1. **How do you debug an internal database without exposing it to the internet?**
   > By using `kubectl port-forward` to create a temporary, secure tunnel from my local machine directly to the internal Pod.
2. **How do you monitor live resource usage in a cluster?**
   > By ensuring the `metrics-server` is installed and using `kubectl top nodes` or `kubectl top pods`.
3. **What is the command to copy a file out of a running container?**
   > `kubectl cp <pod-name>:/path/in/container /local/path`
4. **Why is alias configuration important in Kubernetes?**
   > Typing `k` instead of `kubectl` and enabling `bash` autocomplete significantly speeds up incident response and is essential for passing the CKA exam.
5. **How does traffic flow in a 3-tier Kubernetes architecture?**
   > Internet ➡️ LoadBalancer Service ➡️ Frontend Deployment ➡️ Backend ClusterIP Service ➡️ Backend Deployment ➡️ Database ClusterIP Service ➡️ Database Pod.
