## 🛠️ Execution & Architecture

### 1️⃣ Module Registry & Versioning Analysis
Studied `registry.terraform.io` to analyze how top modules (`terraform-aws-vpc`, `terraform-aws-eks`) define their inputs and outputs. Learned how to consume external modules using Git tags and the Pessimistic Constraint Operator for version safety.

```hcl
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "~> 5.0"
  
  name = "my-vpc"
  cidr = "10.0.0.0/16"
}
```

### 2️⃣ Semantic Versioning & CHANGELOG.md
Integrated a standard `CHANGELOG.md` adhering to [Keep a Changelog](https://keepachangelog.com/en/1.0.0/) and [SemVer](https://semver.org/). Documented the release of `v1.0.0` for Project 1, capturing features like Zero-Trust Security Groups and dynamic Auto Scaling inputs.

### 3️⃣ Auto-Generated Documentation (`terraform-docs`)
Instead of manually typing out Terraform variable descriptions and output names, I utilized `terraform-docs` to dynamically parse the HCL and generate a beautiful `TERRAFORM.md` file for the entire architecture.

```bash
# Standard workflow for auto-documentation
terraform-docs markdown . > TERRAFORM.md
```

### 4️⃣ Continuous Integration (GitHub Actions)
Bootstrapped the `.github/workflows/terraform.yml` pipeline to automatically execute `terraform fmt -check` and `terraform validate` on every Push and Pull Request. This ensures no syntactically broken code ever hits the `main` branch.
