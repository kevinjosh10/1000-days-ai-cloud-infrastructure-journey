## 🎯 Objective

### 2️⃣ Wrote First Terratest (`TestVPCModule`)

Studied how to completely automate the `terraform plan` and `apply` lifecycle.

Learned:
- Wrote a Go function to configure the path to the Terraform module
- Used `terraform.InitAndApply()` to automatically deploy the infrastructure
- Used `terraform.Output()` and `assert.NotEmpty()` to programmatically verify the VPC was created
- **Crucial:** Used `defer terraform.Destroy()` to guarantee the infrastructure is torn down at the end of the test, even if the assertions fail

Understood:
- Automated testing eliminates human error and verification bias
- The `defer` statement ensures we don't accidentally leave expensive AWS resources running and burning money

---

### 3️⃣ Mastered End-to-End Testing with HTTP Helpers

Studied how to verify the actual application behavior, not just the infrastructure state.

Learned:
- Extracted the dynamic ALB DNS name from the Terraform outputs
- Used `http_helper.HttpGetWithRetry` to make real HTTP GET requests to the load balancer
- Configured the test to retry 30 times with a 5-second sleep (allowing EC2 instances time to boot and pass health checks)
- Asserted that the server returns a strict `200 OK` status code

Understood:
- True End-to-End (E2E) testing proves that the infrastructure actually serves traffic successfully
- Testing the network path (VPC -> ALB -> ASG -> EC2) is far more valuable than just checking if a resource exists

---

### 4️⃣ Understood the Terraform Testing Pyramid

Studied the economics and execution times of different testing tiers.

Learned:
- **Unit Tests:** Fast (seconds). Uses tools like OPA/Conftest against `terraform plan` outputs. No actual resources are deployed.
- **Integration Tests:** Medium (minutes). Deploys a single isolated module (like a VPC) to an AWS sandbox and destroys it.
- **E2E Tests:** Slow (15+ minutes). Deploys the entire global architecture.

Understood:
- Running E2E tests on every single code commit is too expensive and slow
- Tests must be strategically layered to balance developer feedback speed with production safety

---

### 5️⃣ Automated Pipeline Enforcement (GitHub Actions)

Practiced integrating Terratest directly into CI/CD.

Command studied:
    go test -v -timeout 60m ./...

Learned:
- Configured a GitHub Action to trigger whenever a Pull Request modifies Terraform code
- The pipeline spins up a runner, assumes an AWS IAM Role via OIDC, and runs the Go tests
- Set a generous `60m` timeout because infrastructure provisioning takes significantly longer than software compilation

Understood:
- If a developer writes code that breaks the VPC, the Go test fails, the GitHub Action turns red, and the PR is strictly blocked from merging
- This creates an unbreakable, highly trusted infrastructure deployment pipeline
