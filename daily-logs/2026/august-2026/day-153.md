# Day 153 – Terraform Best Practices & Code Review

**Date:** 1 August 2026
**Duration:** ~3.5 Hours
**Focus:** Elevating Terraform code to Enterprise standards via Provider Pinning, DRY Principles, Graph Visualization, and rigorous Code Reviews.

---

## 🎯 Objective

Transition from 'writing Terraform that works' to 'writing Terraform that survives in production'. Enforce strict module standards, eliminate hardcoded values, and visualize complex dependency trees.

Learn:

- The absolute necessity of pinning provider versions (`versions.tf`)
- The Pessimistic Constraint Operator (`~>`) in provider blocks
- Organizing HCL logically (`main.tf`, `variables.tf`, `outputs.tf`, `locals.tf`)
- Visualizing Terraform's mathematical state graph via `terraform graph`
- Identifying and eliminating hardcoded anti-patterns (e.g., hardcoded AMIs)
- Enforcing variable descriptions and standard resource tagging

Practice:

- Implementing The absolute necessity of pinning provider versions (`versions.tf`) across Project 1
- Implementing The Pessimistic Constraint Operator (`~>`) in provider blocks across Project 1
- Implementing Organizing HCL logically (`main.tf`, `variables.tf`, `outputs.tf`, `locals.tf`) across Project 1
- Implementing Visualizing Terraform's mathematical state graph via `terraform graph` across Project 1
- Implementing Identifying and eliminating hardcoded anti-patterns (e.g., hardcoded AMIs) across Project 1
- Implementing Enforcing variable descriptions and standard resource tagging across Project 1
- Creating `versions.tf` in all 4 modules (VPC, RDS, ALB, ASG)
- Refactoring `modules/asg/main.tf` to use a dynamic `data "aws_ami"` block
- Running `terraform graph` and exporting the SVG dependency map
- Adding strict descriptions to all variables across the architecture
