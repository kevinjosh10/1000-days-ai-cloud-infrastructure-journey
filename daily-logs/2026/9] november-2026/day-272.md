# 2. Architectural Overview of `sed`

The name **`sed`** stands for **Stream Editor**. Created between 1973 and 1974 by Lee E. McMahon of Bell Labs, `sed` was designed as a natural evolution of the `ed` interactive line editor, tailored specifically for automated stream pipelines.

Unlike interactive text editors that load an entire file into memory before allowing user navigation, `sed` processes data **sequentially, line-by-line, through a deterministic processing cycle**.

```text
                           The sed Line Execution Cycle
                           
             [ Input Stream / File Inode ]
                           │
                           ▼ (Reads next line, strips newline \n)
               ┌───────────────────────┐
               │     PATTERN SPACE     │ <── Active working buffer
               └───────────┬───────────┘
                           │
             Execute Command Sequence (1 .. N)
             Addressing checks & transformations (s, d, p, c, etc.)
                           │
                           ▼
             Is '-n' (quiet mode) active?
                 ├── NO  ──> Emit Pattern Space to stdout (reappends \n)
                 └── YES ──> Do not print (unless explicit 'p' command triggered)
                           │
                           ▼
               Clear Pattern Space Buffer
                           │
                           ▼
               Fetch next line (Repeat until EOF)
```

### The Two Internal Buffers of `sed`

To manipulate text across multiple lines or retain state, `sed` provides two discrete memory regions:

1. **Pattern Space (Active Working Area):**
   - Holds the current line read from the input stream.
   - All standard editing commands (`s`, `d`, `p`, `y`) operate directly on this buffer.
   - By default, its contents are automatically flushed to standard output at the conclusion of each line cycle, after which it is emptied for the next line.

2. **Hold Space (Auxiliary Long-Term Scratchpad):**
   - A secondary memory buffer that preserves text across line cycles.
   - Commands do not operate directly on the hold space; data must be copied or exchanged between the pattern space and hold space using dedicated memory instructions:
     - `h` / `H`: Copy / Append Pattern Space to Hold Space.
     - `g` / `G`: Copy / Append Hold Space to Pattern Space.
     - `x`: Exchange contents of Pattern Space and Hold Space.

```text
   ┌─────────────────────────────────────────────────────────────┐
   │                        MEMORY MODEL                         │
   │                                                             │
   │    ┌──────────────────┐               ┌──────────────────┐  │
   │    │  PATTERN SPACE   │ ──  h / H  ──>│    HOLD SPACE    │  │
   │    │  (Active Line)   │ <── g / G  ── │  (Saved Memory)  │  │
   │    └──────────────────┘               └──────────────────┘  │
   │             │          ▲             ▲                      │
   │             │          └────  x  ────┘                      │
   │             ▼                                               │
   │       Standard Output                                       │
   └─────────────────────────────────────────────────────────────┘
```

# 3. Addressing Schemes in `sed`

By default, any command passed to `sed` executes unconditionally against **every line** in the stream. Addressing allows an engineer to restrict command execution to specific line numbers, ranges, patterns, or alternating steps.

```text
Syntax:  [address]command  or  [address1,address2]command
```

### A. Line Number Addressing

| Address Expression | Description | Example |
|---|---|---|
| `N` | Targets exactly line number `N` | `sed -n '1p' file` (prints line 1 only) |
| `N,M` | Targets inclusive range from line `N` to line `M` | `sed -n '3,7p' file` (prints lines 3 through 7) |
| `$` | Targets the last line of the file/stream | `sed -n '$p' file` (prints final line) |
| `N,$` | Targets from line `N` to the end of the file | `sed '5,$d' file` (deletes lines 5 to end; keeps 1–4) |

### B. Regex Pattern Addressing

Regex delimiters (`/pattern/`) identify lines based on content rather than position:

```bash
# Print only lines containing the keyword 'ERROR'
sed -n '/ERROR/p' app.log

# Delete all lines containing 'DEBUG'
sed '/DEBUG/d' app.log

# Range matching: Execute substitution only between 'BEGIN' and 'END' markers
sed '/BEGIN_CERTIFICATE/,/END_CERTIFICATE/s/old/new/g' cert.pem
```

### C. Step Addressing (GNU sed Extension)

Step addressing uses the syntax `first~step`:

```bash
# Print alternate lines starting from line 1 (odd lines: 1, 3, 5, 7...)
sed -n '1~2p' hosts.txt

# Print alternate lines starting from line 2 (even lines: 2, 4, 6, 8...)
sed -n '2~2p' hosts.txt
```

### D. Inverted Addressing (`!`)

The exclamation mark `!` inverts the address matching criteria:

```bash
# Delete all lines EXCEPT lines 1 through 10 (keeps lines 1-10)
sed '1,10!d' file.txt

# Print all lines EXCEPT those containing 'INFO'
sed -n '/INFO/!p' app.log
```

# 4. Substitution Command Mastery (`s/pattern/replacement/flags`)

The substitute command (`s`) is the most frequently utilized operation in `sed`.

$$\text{Syntax:} \quad \mathbf{s/}\text{pattern}\mathbf{/}\text{replacement}\mathbf{/}\text{flags}$$

### Substitution Operational Flags

| Flag | Name | Functionality |
|---|---|---|
| `g` | Global | Replaces **all** occurrences on each line instead of just the first occurrence. |
| `i` / `I` | Case-Insensitive | Matches pattern regardless of uppercase or lowercase characters. |
| `p` | Print | Prints the pattern space to standard output **only if** a substitution was made. |
| `w <file>` | Write | Appends the transformed line to an external file **only if** substitution succeeded. |
| `N` (1, 2...) | Nth Match | Replaces only the N-th occurrence of the pattern on each matching line. |

### Practical Substitution Examples

```bash
# 1. Basic first occurrence replacement
sed 's/localhost/127.0.0.1/' config.env

# 2. Global replacement (all instances per line)
sed 's/AWS/Amazon/g' cloud_matrix.txt

# 3. Case-insensitive global replacement
sed 's/linux/Ubuntu/gi' platform.info

# 4. Selective printing: Only emit lines where replacement occurred (requires -n)
sed -n 's/cluster-east/cluster-west/p' topology.conf

# 5. Selective writing: Save modified lines directly to audit output
sed -n 's/DEPRECATED/OBSOLETE/w migrated.log' services.list

# 6. Replace only the second occurrence on a line
sed 's/admin/superuser/2' access_control.csv
```

# 5. Custom Delimiters & Leaning Toothpick Syndrome (LTS)

When working with Linux file paths, URIs, endpoints, and regular expressions, the default forward slash delimiter (`/`) creates severe readability and syntax hazards known as **Leaning Toothpick Syndrome (LTS)**.

### The Problem: Escaped Slashes

To substitute a path like `/var/log/httpd/` with `/var/log/nginx/` using default delimiters, every slash must be escaped:

```bash
# Unreadable and prone to syntax errors
sed 's/\/var\/log\/httpd\//\/var\/log\/nginx\//g' webserver.conf
```

### The Solution: Arbitrary Delimiters

`sed` permits any single character immediately following the `s` command to act as the delimiter:

```bash
# Delimiter: '#' (Highly recommended for URLs and filesystem paths)
sed 's#/var/log/httpd/#/var/log/nginx/#g' webserver.conf
sed 's#http://#https://#g' api_endpoints.txt

# Delimiter: '|' (Clean for regexes and pipelines)
sed 's|old_directory|new_directory|g' paths.conf

# Delimiter: '@' (Ideal for email addresses or complex strings)
sed 's@dev@prod@g' cluster.yaml

# Delimiter: ':' (Common in configuration assignments)
sed 's:port=8080:port=443:g' service.env
```

# 6. In-Place File Editing (`sed -i`): OS Mechanics & Platform Traps

In modern DevOps automation, scripts frequently modify configuration files directly on disk.

```bash
sed -i 's/APP_PORT=3000/APP_PORT=8080/' /etc/app/app.conf
```

### The Low-Level OS Mechanics of `sed -i`

Contrary to intuitive belief, `sed -i` **does not open the file and overwrite its blocks in-place**. Doing so would be catastrophic if line lengths changed or if a process crashed mid-write.

Instead, `sed -i` performs an **atomic file replacement**:
1. It opens the source file for reading.
2. It creates a temporary hidden file in the same directory (e.g. `sedXXXXXX`).
3. It streams the modified lines into the temporary file.
4. If a backup extension was specified (e.g. `-i.bak`), it hard-links or renames the original file to `file.bak`.
5. It issues a `rename(2)` system call, moving the temporary file over the original file name.

```text
               OS Mechanics of In-Place Modification (sed -i)
               
  1. Original File (Inode 104251) ───[ Read Stream ]───> sed Engine
                                                             │
  2. Temporary File (Inode 104899) <──[ Write Stream ]───────┘
                                                             │
  3. Backup Step: Inode 104251 renamed to app.conf.bak       │
                                                             ▼
  4. Atomic Rename: Inode 104899 renamed to app.conf (Replaces original inode)
```

> [!WARNING]
> **Container Mount & Inode Invalidation Hazard:**  
> Because `sed -i` unlinks the original file and renames a new temporary inode over it, using `sed -i` on a file mounted directly into a Docker container (e.g., `docker run -v /host/app.conf:/etc/app.conf`) can break the Docker bind mount or fail with `Device or resource busy`. In container entrypoints, prefer copying or using standard redirects (`cat file | sed ... > temp && cat temp > file`).

### GNU sed vs. BSD / macOS sed Divergence

One of the most notorious cross-platform scripting incompatibilities exists between GNU sed (standard on Linux/WSL) and BSD sed (standard on macOS and FreeBSD):

| Scenario | GNU sed (Linux) | BSD sed (macOS / FreeBSD) | Portable Shell Pattern |
|---|---|---|---|
| **In-place with backup** | `sed -i.bak 's/a/b/' file` | `sed -i.bak 's/a/b/' file` | `cp file file.bak && sed -i ...` |
| **In-place WITHOUT backup** | `sed -i 's/a/b/' file` | `sed -i '' 's/a/b/' file` | *Fails on opposite OS!* |

- On Linux, passing `sed -i ''` causes GNU sed to treat `''` as the sed script and the script as the target file, resulting in an error.
- On macOS, running `sed -i 's/a/b/' file` causes BSD sed to treat `'s/a/b/'` as the backup extension, resulting in an error or bizarre `.bak` files.

**Cross-Platform Portable Engineering Pattern:**
```bash
if sed --version >/dev/null 2>&1; then
    # GNU sed
    sed -i -e 's/old/new/g' "$TARGET_FILE"
else
    # BSD / macOS sed
    sed -i '' -e 's/old/new/g' "$TARGET_FILE"
fi
```

# 7. Practical Infrastructure Applications

### A. Removing Comments & Documentation
```bash
# Strip full-line comments and comments with leading whitespace
sed '/^[[:space:]]*#/d' /etc/nginx/nginx.conf
```

### B. Stripping Blank and Whitespace-Only Lines
```bash
# Strip empty lines (^$) and lines containing only tabs/spaces
sed '/^[[:space:]]*$/d' server.env
```

### C. Updating Key-Value Configuration Settings
```bash
# Safely replace key value regardless of previous assignment
sed -i.bak 's/^APP_PORT=.*/APP_PORT=8080/' app.conf
sed -i.bak 's/^APP_ENV=.*/APP_ENV=production/' app.conf
```

### D. Normalizing Insecure Endpoints
```bash
# Convert all HTTP API endpoints to HTTPS
sed -i.bak 's#http://#https://#g' microservices.env
```

### E. Chaining Multiple Transformations
```bash
# Execute chained transformations cleanly using multiple -e flags
sed -i.bak \
    -e '/^[[:space:]]*#/d' \
    -e '/^[[:space:]]*$/d' \
    -e 's/^APP_PORT=.*/APP_PORT=8080/' \
    -e 's/^APP_ENV=.*/APP_ENV=production/' \
    -e 's#http://#https://#g' \
    app.conf
```

Usage: ${0##*/} [OPTIONS] <config-file>

Automated Configuration Sanitizer using Linux Stream Editor (sed).

Transformations Performed:
  1. Creates automatic backup copy (<config-file>.bak)

    usage
    exit 1

    usage
    exit 0

# 10. Technical Interview Scenarios & Deep-Dive Answers

### Q1: Explain the difference between `sed`'s Pattern Space and Hold Space. When would an engineer use Hold Space?
**Answer:**
- **Pattern Space** is the primary working memory buffer. It temporarily holds the current line read from the stream, undergoes command transformations, and is flushed to stdout at the end of the line cycle.
- **Hold Space** is a secondary persistent memory buffer. It retains text across line cycles and is never automatically flushed or erased between lines.
- **Use Case:** Hold space is required for multiline operations, reversing line order (`sed -n '1!G;h;$p' file`), matching blocks of text spanning multiple lines, or storing a header line on line 1 and appending it to every subsequent record.

### Q2: Why can `sed -i` break Docker volume mounts or symlinks, and how do you prevent this?
**Answer:**
- `sed -i` performs an atomic write by creating a temporary file and renaming it over the destination file. This operation creates a **new inode**.
- In Docker bind mounts (`-v /host/file:/container/file`), the mount is tied to the original inode. When `sed -i` replaces the file inside the container, the link between the host and container inode is severed, or the operation fails with `Device or resource busy`.
- **Prevention:** To preserve the inode, either copy the modified content over the existing inode (`sed '...' file > temp && cat temp > file`), or use GNU sed's `--copy` flag (`sed -i --copy '...' file`) which instructs sed to overwrite the existing file buffer rather than executing a rename.

### Q3: Why does `sed -i 's/foo/bar/' file.txt` fail on macOS / BSD while succeeding on Linux?
**Answer:**
- On Linux (GNU sed), the `-i` flag takes an *optional* backup suffix argument. If omitted, no backup is created.
- On macOS / BSD sed, the `-i` flag requires an *explicit* argument. If no backup is wanted, an empty string argument must be provided: `sed -i '' 's/foo/bar/' file.txt`. Passing no argument causes BSD sed to misinterpret `'s/foo/bar/'` as the backup extension and the filename as the script.

### Q4: What is the purpose of the `&` character in the replacement string of `sed`'s `s///` command?
**Answer:**
- The `&` character represents the **entire text segment matched by the search pattern**.
- It allows wrapping, prefixing, or suffixing matched tokens without requiring capture groups:
  ```bash
  # Wrap every IP address in square brackets
  sed -E 's/[0-9]+\.[0-9]+\.[0-9]+\.[0-9]+/\[&\]/g' log.txt
  
  # Prefix all numbers with USD currency symbol
  sed -E 's/[0-9]+/$\&/g' prices.txt
  ```

### Q5: How does `sed -n 's/foo/bar/p'` improve performance over running `sed 's/foo/bar/' | grep 'bar'`?
**Answer:**
- `sed -n 's/foo/bar/p'` performs both the substitution and the filtering in a single process inside a single stream cycle.
- The pipeline approach (`sed ... | grep ...`) spawns two separate subshell processes, allocates an inter-process pipe buffer (`|`), requires context switching between processes, and runs a secondary pattern match over the entire stream. In large log analysis (gigabytes), the single-pass `sed -n ... p` command is dramatically faster and consumes fewer CPU cycles.

# 11. Key Concepts Summary & Quick Reference Cheat Sheet

```bash
# ------------------------------------------------------------------------------
# SED FUNDAMENTALS CHEAT SHEET
# ------------------------------------------------------------------------------

# Basic Substitutions
sed 's/foo/bar/' file.txt              # Replace first match per line
sed 's/foo/bar/g' file.txt             # Replace all matches per line (global)
sed 's/foo/bar/gi' file.txt            # Case-insensitive global replacement
sed -n 's/foo/bar/p' file.txt          # Print only lines where replacement occurred
sed -n 's/foo/bar/w out.txt' file.txt  # Write replaced lines to out.txt

# Custom Delimiters (Preventing LTS)
sed 's#http://#https://#g' file.txt    # Delimiter '#'
sed 's|/var/log|/opt/log|g' file.txt   # Delimiter '|'
sed 's@dev@prod@g' file.txt            # Delimiter '@'

# Line Addressing & Deletion
sed -n '1p' file.txt                   # Print line 1 only
sed -n '3,7p' file.txt                 # Print lines 3 to 7
sed -n '$p' file.txt                   # Print last line
sed -n '1~2p' file.txt                 # Print odd lines (GNU extension)
sed '/pattern/d' file.txt              # Delete lines matching pattern
sed '1,5d' file.txt                    # Delete lines 1 through 5
sed '/^[[:space:]]*#/d' file.txt       # Delete comment lines
sed '/^[[:space:]]*$/d' file.txt       # Delete blank / whitespace lines

# In-Place File Editing
sed -i.bak 's/old/new/g' file.txt      # Edit in place with .bak backup
sed -i 's/old/new/g' file.txt          # Edit in place without backup (Linux)
sed -i '' 's/old/new/g' file.txt       # Edit in place without backup (macOS)

# Chained Operations
sed -i.bak -e 's/a/b/' -e 's/c/d/' file.txt
```
