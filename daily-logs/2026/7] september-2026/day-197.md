### 2. Linux Filesystem Hierarchy

```text
/
```

Learned the purpose of the major FHS directories:

```text
/
├── bin
├── boot
├── dev
├── etc
├── home
├── mnt
├── opt
├── proc
├── root
├── run
├── sbin
├── sys
├── tmp
├── usr
└── var
```

### 3. Important Directories

Studied the role of:

* `/etc` — system and service configuration
* `/var` — variable data and logs
* `/var/log` — system/application logs
* `/home` — normal users' home directories
* `/root` — root user's home directory
* `/tmp` — temporary files
* `/usr` — user-space programs and data
* `/bin` — essential user commands
* `/sbin` — system administration commands
* `/dev` — device files
* `/proc` — process and kernel information
* `/sys` — kernel and hardware/device information
* `/opt` — optional/third-party software
* `/mnt` — filesystem mounting location
* `/boot` — boot-related files

### 5. Linux File Types

Learned to identify file types using `ls -l`.

| Symbol | Type             |
| ------ | ---------------- |
| `-`    | Regular file     |
| `d`    | Directory        |
| `l`    | Symbolic link    |
| `c`    | Character device |

Understood that:

### 7. `/proc` Exploration

Explored Linux's virtual `/proc` filesystem.

Inspected:

```bash
cat /proc/cpuinfo
cat /proc/meminfo
cat /proc/uptime
```

Understood that `/proc` provides runtime information about:

* CPU
* Memory
* Processes
* Kernel/system state

### 8. `/sys` Exploration

Explored:

```bash
ls /sys
```

Learned that `/sys` exposes information and interfaces related to:

* Hardware
* Devices
* Kernel subsystems
* System configuration

### 9. `/dev` Exploration

Explored device files and learned the Linux concept:

> **"Everything is a file"**

Investigated:

```bash
/dev/null
```

and understood how device files provide interfaces to hardware and special system devices.

### 10. Symbolic Links

Created and inspected a symbolic link:

```bash
ln -s original.txt link.txt
```

Verified it using:

```bash
ls -l
file link.txt
```

Understood that a symbolic link references another filesystem path.

## ☁️ Cloud Infrastructure Connection

Today's concepts directly connect to future cloud infrastructure work.

On a Linux EC2 server, troubleshooting often involves:

```text
Application problem
       ↓
Configuration → /etc
       ↓
Logs → /var/log
       ↓
Processes → /proc
       ↓
Memory/CPU → /proc
       ↓
Devices → /dev
       ↓
Hardware/Kernel → /sys
```

Understanding the filesystem will later make it easier to work with:

* AWS EC2
* Docker
* Kubernetes
* Terraform
* CI/CD runners
* Linux servers
* Systemd
* Networking
* Storage
* Production troubleshooting

## 🧠 Key Mental Model

Linux is not just a collection of commands.

The filesystem provides an organized interface to the entire system:

```text
                 Linux System
                      │
                      ▼
                     /
        ┌─────────────┼─────────────┐
        │             │             │
      /etc           /var          /home
   Configuration     Logs          Users
        │             │
        └──────┬──────┘
               │
             Linux
               │
      ┌────────┼────────┐
      │        │        │
    /proc     /sys     /dev
   Processes  Hardware Devices
```
