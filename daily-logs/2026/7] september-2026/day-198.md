# 📚 What I Learned

## 1. Directory Creation — `mkdir`

Learned how to create directories using:

```bash
mkdir directory
```

For nested directories:

```bash
mkdir -p project/src/logs
```

`-p` creates parent directories automatically if they don't already exist.

I also learned brace expansion:

```bash
mkdir -p /practice/{docs,scripts,logs,backups/{daily,weekly}}
```

This efficiently creates multiple directories at once.

---

## 2. File Creation — `touch`

Used `touch` to create empty files:

```bash
touch file.txt
```

Multiple files:

```bash
touch file1.txt file2.txt file3.txt
```

Using brace expansion:

```bash
touch file{1..5}.txt
```

This creates:

```text
file1.txt
file2.txt
file3.txt
file4.txt
file5.txt
```

---

## 3. Copying Files — `cp`

Learned how to copy files:

```bash
cp file.txt backup.txt
```

Copy a file into a directory:

```bash
cp file.txt backups/
```

Copy directories recursively:

```bash
cp -r project backup/
```

`-r` means recursive.

---

## 4. Moving & Renaming — `mv`

Move a file:

```bash
mv file.txt docs/
```

Rename a file:

```bash
mv old.txt new.txt
```

Linux uses `mv` for both moving and renaming.

---

## 5. Removing Files — `rm`

Delete a file:

```bash
rm file.txt
```

Delete multiple files:

```bash
rm file1.txt file2.txt
```

Delete files using globbing:

```bash
rm *.log
```

Recursive deletion:

```bash
rm -r directory
```

Force deletion:

```bash
rm -f file.txt
```

### ⚠️ Important

I learned that `rm -rf` is a powerful and potentially dangerous command because it can recursively delete large amounts of data.

Destructive commands should always be used carefully, especially when variables are involved in automation scripts.

---

## 6. Removing Empty Directories — `rmdir`

`rmdir` removes empty directories:

```bash
rmdir empty_folder
```

Unlike `rm -r`, it will not remove a directory containing files.

# 🔗 7. Hard Links — `ln`

Created hard links using:

```bash
ln original.txt copy.txt
```

A hard link points to the same underlying inode.

I used:

```bash
ls -li original.txt copy.txt
```

to compare inode numbers.

### Key concept

```text
original.txt ──┐
               ├──> Same inode
copy.txt ──────┘
```

---

# 🔗 8. Symbolic Links — `ln -s`

Created symbolic links using:

```bash
ln -s original.txt shortcut.txt
```

A symbolic link points to the path of another file.

Check it with:

```bash
ls -l shortcut.txt
```

Example:

```text
shortcut.txt -> original.txt
```

### Hard Link vs Symbolic Link

| Hard Link                         | Symbolic Link              |
| --------------------------------- | -------------------------- |
| `ln`                              | `ln -s`                    |
| Points to inode                   | Points to path             |
| Usually cannot cross filesystems  | Can cross filesystems      |
| Generally cannot link directories | Can link directories       |
| Target rename does not break it   | Target rename can break it |

# 🌟 9. Wildcards / Globbing

Learned how Bash uses patterns to match filenames.

### `*`

Matches zero or more characters:

```bash
ls *.txt
```

Example matches:

```text
file.txt
notes.txt
backup.txt
```

### `?`

Matches exactly one character:

```bash
ls file?.txt
```

Can match:

```text
file1.txt
fileA.txt
```

but not:

```text
file10.txt
```

### `[]`

Matches one character from a specified set or range:

```bash
ls file[1-3].txt
```

Matches:

```text
file1.txt
file2.txt
file3.txt
```

# 🧩 10. Brace Expansion

Learned that Bash can generate multiple strings using `{}`.

Example:

```bash
echo file{1..5}.txt
```

Produces:

```text
file1.txt
file2.txt
file3.txt
file4.txt
file5.txt
```

Another example:

```bash
echo {jan,feb,mar}.log
```

Produces:

```text
jan.log
feb.log
mar.log
```

### Brace Expansion vs Globbing

Brace expansion:

```bash
{1..5}
```

generates strings.

Globbing:

```bash
*.txt
```

matches existing filesystem entries.

# ⚙️ 11. Command Substitution

Learned how to use the output of one command inside another command.

Syntax:

```bash
$(command)
```

Example:

```bash
echo "Today is $(date)"
```

Store command output in a variable:

```bash
CURRENT_DIR=$(pwd)
echo "$CURRENT_DIR"
```

This is useful for dynamic paths and automation.

# 🛡️ 12. Defensive Bash Scripting

One of the most important concepts from today.

A script should not blindly continue when something goes wrong.

Without error handling:

```text
Command fails
     ↓
Script continues
     ↓
More commands execute
     ↓
Potentially dangerous result
```

With defensive scripting:

```text
Command fails
     ↓
Error detected
     ↓
Error logged
     ↓
Script stops or handles the failure
```

---

# 🚨 13. `set -e`

Learned about:

```bash
set -e
```

This makes Bash generally exit when a command fails instead of blindly continuing.

Example:

```bash
#!/bin/bash

set -e

mkdir /some/path
cp important.txt /some/path

echo "Backup completed"
```

If an important command fails, the script can stop rather than continuing into an invalid state.

---

# 🚨 14. `trap`

Learned how `trap` can execute commands when certain events occur.

Example:

```bash
trap 'echo "ERROR: Script failed at line $LINENO"' ERR
```

This helps identify where a script failed.

It can be combined with logging to make scripts easier to troubleshoot.

---

# 📝 15. Logging

Learned how scripts can record their actions.

Example:

```bash
LOG_FILE="/tmp/setup.log"

echo "Starting setup..." >> "$LOG_FILE"
```

`>>` appends to a file.

Compared with:

```bash
>
```

which overwrites the file.

Logging is important for infrastructure automation because it provides a record of what the script attempted to do.

---

# 🐛 16. Debugging with `bash -x`

Learned how to trace Bash scripts:

```bash
bash -x setup_practice_env.sh
```

This shows the commands Bash executes.

Useful for finding:

* Incorrect variables
* Wrong paths
* Failed commands
* Unexpected execution flow
* Script logic problems

---

# 🔢 17. Exit Codes — `$?`

Learned that Linux commands return an exit status.

Check the previous command:

```bash
echo $?
```

Generally:

```text
0       → Success
Non-zero → Failure
```

This is fundamental to Bash error handling and automation.
