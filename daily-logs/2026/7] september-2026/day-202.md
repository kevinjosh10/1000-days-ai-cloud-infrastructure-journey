# 🧠 Part A — Storage

## 1. Linux Storage Stack

Linux storage can be understood as a layered system:

```text
Physical Disk
     ↓
Partition Table
     ↓
Partition
     ↓
Filesystem
     ↓
Mount Point
     ↓
Files & Directories
```

Example:

```text
/dev/sda
   │
   ├── /dev/sda1
   │       ↓
   │     ext4
   │       ↓
   │      /
   │
   └── /dev/sda2
           ↓
         ext4
           ↓
         /home
```

Cloud equivalent:

```text
AWS EC2
   ↓
EBS Volume
   ↓
Partition
   ↓
Filesystem
   ↓
Mount Point
   ↓
Application Data
```

---

# 2. Block Devices vs Character Devices

Linux represents devices as files under `/dev`.

## Block Devices

Block devices work with data in blocks.

Examples:

```text
/dev/sda
/dev/sdb
/dev/nvme0n1
```

Common examples:

* HDDs
* SSDs
* NVMe drives
* AWS EBS volumes

Mental model:

```text
Block Device → Storage
```

---

## Character Devices

Character devices handle data as a stream of characters.

Examples:

```text
/dev/tty
/dev/console
```

Commonly associated with:

* Terminals
* Serial devices
* Input/output streams

Mental model:

```text
Character Device → Data Stream
```

---

# 3. Partitions

A partition divides a physical disk into logical sections.

Example:

```text
1 TB Disk

+------------------------------------------+
| Partition 1 | Partition 2 | Partition 3 |
|   200 GB    |   300 GB    |   500 GB    |
+------------------------------------------+
```

A Linux system might look like:

```text
/dev/nvme0n1
       │
       ├── nvme0n1p1 → /
       ├── nvme0n1p2 → /home
       └── nvme0n1p3 → /data
```

Each partition can contain its own filesystem.

---

# 4. MBR vs GPT

Partition tables define how partitions are organized on a disk.

## MBR

MBR = Master Boot Record.

It is an older partitioning scheme.

Limitations:

* Traditional maximum disk size around 2 TB
* Usually limited to 4 primary partitions
* Associated with older BIOS-based systems

---

## GPT

GPT = GUID Partition Table.

It is the modern partitioning scheme.

Advantages:

* Supports very large disks
* Supports many partitions
* Works naturally with UEFI
* Stores backup partition-table information

Modern systems generally use:

```text
GPT + UEFI
```

instead of:

```text
MBR + Legacy BIOS
```

### Key takeaway

```text
MBR → Older partition scheme
GPT → Modern partition scheme
```

---

# 5. Linux Filesystems

A partition needs a filesystem to organize files.

Common Linux filesystems:

```text
ext4
XFS
Btrfs
tmpfs
```

---

## ext4

ext4 is a common general-purpose Linux filesystem.

Typical use cases:

* Linux servers
* General-purpose storage
* Application servers
* Root filesystems

Mental model:

```text
ext4 → General-purpose Linux filesystem
```

---

## XFS

XFS is a mature filesystem commonly used in enterprise Linux environments.

Commonly seen in:

* RHEL-based systems
* Enterprise servers
* Large storage environments

Mental model:

```text
XFS → Enterprise-oriented filesystem
```

---

## Btrfs

Btrfs is a feature-rich filesystem.

Important features include:

* Snapshots
* Subvolumes
* Checksums
* Copy-on-write
* Advanced filesystem management

Mental model:

```text
Btrfs
 ├── Snapshots
 ├── Subvolumes
 ├── Checksums
 └── Copy-on-write
```

---

## tmpfs

`tmpfs` is a temporary filesystem that primarily uses RAM.

Conceptually:

```text
tmpfs
  ↓
RAM
  ↓
/mnt/ramdisk
```

It is useful for:

* Temporary data
* High-speed temporary files
* Runtime data
* Temporary application caches

Data stored in tmpfs is not intended for persistent storage.

# 6. LVM

LVM = Logical Volume Manager.

Instead of directly managing:

```text
Disk → Partition → Filesystem
```

LVM introduces an abstraction layer:

```text
Physical Volume
       ↓
Volume Group
       ↓
Logical Volume
       ↓
Filesystem
       ↓
Mount Point
```

The core sequence to remember is:

```text
PV → VG → LV
```

---

## Physical Volume — PV

A physical storage device or partition prepared for LVM.

Example:

```text
/dev/sdb
```

---

## Volume Group — VG

A storage pool made from one or more physical volumes.

Example:

```text
PV1 = 100 GB
PV2 = 100 GB

      ↓

VG = 200 GB
```

---

## Logical Volume — LV

Storage allocated from the volume group.

Example:

```text
VG = 200 GB

├── LV1 = 50 GB
├── LV2 = 50 GB
└── LV3 = 100 GB
```

Then:

```text
LV
 ↓
ext4
 ↓
/data
```

LVM provides flexible storage management compared with traditional fixed partitions.

---

# 7. Mounting

Linux doesn't normally use Windows-style drive letters:

```text
C:
D:
E:
```

Instead, filesystems are attached to directories.

This process is called **mounting**.

Example:

```text
/dev/sdb1
    ↓
  mount
    ↓
 /data
```

The filesystem is now accessible through:

```bash
cd /data
```

---

# 8. `mount`

View mounted filesystems:

```bash
mount
```

A cleaner view:

```bash
findmnt
```

Disk usage:

```bash
df -h
```

---

# 9. `umount`

Unmount a filesystem:

```bash
sudo umount /mnt/ramdisk
```

Important:

```text
umount
```

not:

```text
unmount
```

---

# 10. `/etc/fstab`

`/etc/fstab` contains filesystem mount configuration.

View it:

```bash
cat /etc/fstab
```

A typical entry:

```text
UUID=xxxx-xxxx   /data   ext4   defaults   0   2
```

The six columns are:

```text
1. Device / UUID
2. Mount point
3. Filesystem type
4. Mount options
5. Dump
6. fsck order
```

Example:

```text
UUID=xxxx-xxxx
        ↓
Filesystem identifier

/data
  ↓
Mount point

ext4
  ↓
Filesystem

defaults
  ↓
Mount options

0
↓
Dump field

2
↓
fsck check order
```

### Important

Do not casually modify `/etc/fstab` on a production system.

A bad configuration can cause mounting failures during boot.

# 18. Filesystem Information

First identify filesystems:

```bash
lsblk -f
```

For an ext filesystem:

```bash
sudo tune2fs -l /dev/<device>
```

For XFS:

```bash
sudo xfs_info /mount/point
```

Only use the command appropriate for the filesystem actually present.

---

# 19. Filesystem Check — Dry Run

For an appropriate unmounted filesystem:

```bash
sudo fsck -n /dev/<device>
```

The `-n` option prevents changes.

Important:

> Never blindly run filesystem repair commands against a mounted root filesystem.

---

# 20. Create a tmpfs RAM Disk

Create the mount point:

```bash
sudo mkdir -p /mnt/ramdisk
```

Mount a 100 MB tmpfs:

```bash
sudo mount -t tmpfs -o size=100M tmpfs /mnt/ramdisk
```

Check:

```bash
df -hT /mnt/ramdisk
```

Create a test file:

```bash
echo "Day 202 Linux Storage Lab" | sudo tee /mnt/ramdisk/test.txt
```

Read it:

```bash
cat /mnt/ramdisk/test.txt
```

List the directory:

```bash
ls -lah /mnt/ramdisk
```

Unmount:

```bash
sudo umount /mnt/ramdisk
```

Check again:

```bash
ls -lah /mnt/ramdisk
```

The temporary data disappears after the filesystem is unmounted.

# 📦 Part B — Package Management

## 21. What Is a Package Manager?

A package manager handles software installation and maintenance.

Typical lifecycle:

```text
Search
  ↓
Download
  ↓
Resolve Dependencies
  ↓
Install
  ↓
Update
  ↓
Remove
```

---

# 22. APT

Debian and Ubuntu commonly use:

```text
apt
```

Search:

```bash
apt search curl
```

Install:

```bash
sudo apt install curl
```

Show information:

```bash
apt show curl
```

Remove:

```bash
sudo apt remove curl
```

Update package metadata:

```bash
sudo apt update
```

Upgrade installed packages:

```bash
sudo apt upgrade
```

---

# 23. `apt update` vs `apt upgrade`

This distinction is important.

## `apt update`

```bash
sudo apt update
```

Refreshes package repository metadata.

It does not normally upgrade installed software by itself.

---

## `apt upgrade`

```bash
sudo apt upgrade
```

Actually upgrades installed packages.

Typical workflow:

```bash
sudo apt update
sudo apt upgrade
```

Mental model:

```text
apt update
    ↓
"What updates are available?"

apt upgrade
    ↓
"Install those updates."
```

---

# 24. YUM / DNF

RHEL-family systems traditionally use:

```text
yum
```

Examples:

```bash
yum search curl
yum install curl
yum update
yum remove curl
```

Modern RHEL-based systems commonly use:

```text
dnf
```

Mental model:

```text
Debian / Ubuntu → apt
RHEL family     → dnf / yum
```

---

# 25. Package Dependencies

Applications often depend on other libraries and packages.

Example:

```text
nginx
 ↓
libA
 ↓
libB
 ↓
libC
```

A package manager resolves these dependencies automatically.

This is one of the major advantages of using package managers.

---

# 26. Package Repositories

Package managers obtain software from repositories.

Conceptually:

```text
Your Server
     │
     │ apt install nginx
     ↓
Package Repository
     │
     ↓
nginx + dependencies
     │
     ↓
Your Server
```

On Debian/Ubuntu systems, repository configuration can be found in:

```bash
cat /etc/apt/sources.list
```

Additional repository definitions may exist under:

```text
/etc/apt/sources.list.d/
```

---

# 27. Installed Packages

On Debian/Ubuntu:

```bash
dpkg -l | head
```

Search installed packages:

```bash
dpkg -l | grep curl
```

On RPM-based systems:

```bash
rpm -qa | head
```

Package information:

```bash
rpm -qi htop
```

---

# 28. Building Software From Source

Sometimes software is distributed as source code instead of a package.

A traditional workflow is:

```bash
./configure
make
sudo make install
```

Conceptually:

```text
Source Code
     ↓
configure
     ↓
Build Configuration
     ↓
make
     ↓
Compile
     ↓
make install
     ↓
System
```

Advantages of package managers compared with manual installation include:

* Dependency management
* Easier updates
* Easier removal
* Package tracking
* Security updates

Manual installation can make system maintenance more difficult because the package manager may not know what was installed.
