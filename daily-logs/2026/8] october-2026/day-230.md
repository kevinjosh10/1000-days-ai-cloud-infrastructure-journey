## 1. What Is CIDR and Why Do We Use It?

In traditional classful networking (RFC 790), IPv4 was partitioned into rigid classes:
- **Class A:** `/8` ($16,777,216$ hosts) — Massive waste for almost all organizations.
- **Class B:** `/16` ($65,536$ hosts) — Too large for most companies, but quickly exhausted.
- **Class C:** `/24` ($256$ hosts) — Too small for medium enterprises ($>254$ hosts required multiple `/24`s, exploding global BGP routing tables).

In 1993, **Classless Inter-Domain Routing (CIDR, RFC 1519)** removed these rigid class boundaries. CIDR allows arbitrary prefix lengths (`/n`) to divide or aggregate IP address spaces flexibly.

## 2. Prefix Length vs. Subnet Mask

An IPv4 address consists of 32 bits. The **prefix length** (e.g., `/24`) specifies how many leading bits are fixed for the **network ID**. The remaining bits identify the **host**.

$$\text{Network Bits } (n) = \text{Prefix Length}$$
$$\text{Host Bits } (h) = 32 - n$$
$$\text{Total Addresses} = 2^h = 2^{(32 - n)}$$

```text
IP: 192.168.10.50 / 26
Prefix Length: /26  ──►  26 Network Bits (Fixed) | 6 Host Bits (Variable)

Subnet Mask in Binary:
11111111 . 11111111 . 11111111 . 11000000
   255   .    255   .    255   .    192       (Dotted-Decimal: 255.255.255.192)
```

### The 8-Bit Octet Pattern Table
Memorizing these 8 numbers allows you to convert any CIDR mask in seconds:

| Bits Borrowed | Binary Octet | Dotted-Decimal Value | Block Size ($256 - \text{Mask}$) |
|:---:|:---:|:---:|:---:|
| 1 | `10000000` | **128** | 128 |
| 2 | `11000000` | **192** | 64 |
| 3 | `11100000` | **224** | 32 |
| 4 | `11110000` | **240** | 16 |
| 5 | `11111000` | **248** | 8 |
| 6 | `11111100` | **252** | 4 |
| 7 | `11111110` | **254** | 2 |
| 8 | `11111111` | **255** | 1 |

## 3. The Prefix Math Engine: Calculating Subnet Boundaries

To calculate the properties of any subnet without a calculator, follow this four-step method:

### The Magic Number (Block Size) Shortcut:
1. **Identify the interesting octet:**  
   - `/1` to `/8`: 1st octet
   - `/9` to `/16`: 2nd octet
   - `/17` to `/24`: 3rd octet
   - `/25` to `/32`: 4th octet
2. **Calculate the Block Size (Magic Number):**
   $$\text{Block Size} = 256 - \text{Mask Value of the Interesting Octet} = 2^{(8 - \text{bits in octet})}$$
3. **Find the Network Address:**  
   Find the multiple of the block size that is less than or equal to the IP's value in that octet.
4. **Find the Broadcast Address:**  
   Next Network Address $- 1$ (or set all host bits to 1).

---

### Step-by-Step Walkthrough: Analyze `10.0.14.73 / 27`

1. **Analyze Prefix:** `/27`
   - Network bits = $27$. Host bits $h = 32 - 27 = 5$.
   - The interesting octet is the **4th octet** (since $27 = 24 + 3$).
   - 3 bits in the 4th octet = `11100000` = `224`.
   - Subnet Mask = `255.255.255.224`.

2. **Compute Block Size:**
   $$\text{Block Size} = 256 - 224 = \mathbf{32}$$
   *(Multiples of 32: 0, 32, 64, 96, 128, ...)*

3. **Locate the 4th Octet:**
   - The IP's 4th octet is `73`.
   - `73` falls between `64` and `96`.
   - Lower multiple = `64` $\rightarrow$ **Network Address:** `10.0.14.64`
   - Next multiple = `96` $\rightarrow$ **Next Subnet:** `10.0.14.96`

4. **Derive the Key Boundaries:**
   - **Network Address:** `10.0.14.64`
   - **Broadcast Address:** `10.0.14.95` ($96 - 1$)
   - **First Usable Host:** `10.0.14.65` ($\text{Network} + 1$)
   - **Last Usable Host:** `10.0.14.94` ($\text{Broadcast} - 1$)
   - **Total IP Addresses:** $2^5 = \mathbf{32}$

## 4. Host Count Formulas: On-Premises vs. Cloud Providers

Why do usable host counts differ between traditional networking and major cloud providers?

```text
                  Total Addresses in /24 (256 IPs)
 ┌──────────────────────────────────────────────────────────────┐
 │ Traditional On-Prem:  254 Usable   │ 2 Reserved (.0, .255)   │
 ├────────────────────────────────────┼─────────────────────────┤
 │ AWS VPC Subnet:       251 Usable   │ 5 Reserved (.0 - .3, .255)
 ├────────────────────────────────────┼─────────────────────────┤
 │ Azure Virtual Network:251 Usable   │ 5 Reserved (.0 - .3, .255)
 ├────────────────────────────────────┼─────────────────────────┤
 │ Google Cloud (GCP):   252 Usable   │ 4 Reserved (.0, .1, .254, .255)
 └────────────────────────────────────┴─────────────────────────┘
```

### 1. Traditional On-Premises: $2^h - 2$
Reserves **2** addresses:
- **First address (`.0`):** Network ID.
- **Last address (`.255`):** Subnet broadcast.

### 2. Amazon Web Services (AWS): $2^h - 5$
AWS reserves **5 IP addresses** in every VPC subnet:
1. **`x.x.x.0`:** Network address.
2. **`x.x.x.1`:** Reserved by AWS for the VPC router.
3. **`x.x.x.2`:** Reserved by AWS for the AmazonProvidedDNS (VPC base $+ 2$).
4. **`x.x.x.3`:** Reserved by AWS for future use.
5. **`x.x.x.255`:** Network broadcast address (AWS does not support broadcast routing, but reserves the address).

*Note: The minimum subnet size supported in AWS VPC is `/28` ($16 - 5 = 11$ usable IPs). AWS does not allow `/29` or smaller for subnets.*

### 3. Microsoft Azure Virtual Networks: $2^h - 5$
Azure also reserves **5 IP addresses** across every subnet:
1. **`x.x.x.0`:** Network address.
2. **`x.x.x.1`:** Default gateway address.
3. **`x.x.x.2`:** Reserved by Azure to map Azure DNS IPs to the VNet space.
4. **`x.x.x.3`:** Reserved by Azure to map secondary Azure DNS IPs.
5. **`x.x.x.255`:** Subnet broadcast address.

### 4. Google Cloud Platform (GCP): $2^h - 4$
GCP VPC subnets are regional and reserve **4 IP addresses**:
1. **`x.x.x.0`:** Network address.
2. **`x.x.x.1`:** Subnet default gateway.
3. **`x.x.x.254` (Second-to-last):** Reserved by GCP for future use.
4. **`x.x.x.255`:** Broadcast address.

## 6. Real-World Engineering Scenarios

### Scenario 1: Multi-Octet Boundary Crossing
**Problem:** What is the network and broadcast address for `172.16.88.200 / 21`?

1. **Find the interesting octet:**  
   Prefix `/21` falls between `/17` and `/24`, so the **3rd octet** is the interesting octet.  
   $21 - 16 = 5$ bits in the 3rd octet.
2. **Calculate the 3rd octet mask & block size:**  
   5 bits = `11111000` = `248`.  
   $$\text{Block Size} = 256 - 248 = \mathbf{8}$$
   Multiples of 8: `0, 8, 16, ..., 80, 88, 96...`
3. **Evaluate 3rd octet (`88`):**  
   `88` is an exact multiple of 8!
   - **Network 3rd octet:** `88`
   - **Next Subnet 3rd octet:** `88 + 8 = 96`
   - **Broadcast 3rd octet:** `96 - 1 = 95`
4. **Fill in remaining octets:**
   - **Network Address:** `172.16.88.0`
   - **Broadcast Address:** `172.16.95.255`
   - **Usable Host Range:** `172.16.88.1` to `172.16.95.254`
   - **Total IPs:** $2^{(32 - 21)} = 2^{11} = 2,048$ addresses.

---

### Scenario 2: Sizing an EKS Cluster Subnet Defensively
**Requirement:** You need to deploy a production Kubernetes (EKS) worker subnet in `us-east-1a`. You anticipate:
- Up to 150 Pods running concurrently (each pod using AWS VPC CNI gets a secondary ENI IP).
- 10 EC2 worker nodes.
- 2 Application Load Balancer nodes.
- Extra capacity for a 50% rolling update surge.

**Calculation:**
1. Base IPs: $150 \text{ (pods)} + 10 \text{ (nodes)} + 2 \text{ (ALB)} = 162 \text{ IPs}$.
2. Rolling update buffer ($+50\%$): $162 \times 1.5 = 243 \text{ IPs}$.
3. AWS reservation requirement: $+5 \text{ IPs}$.  
   $$\text{Total Required} = 243 + 5 = 248 \text{ IPs}$$
4. Compare CIDR options:
   - `/24` gives $256$ total, $251$ usable in AWS.  
     $248 \le 251$, but leaves only 3 spare IPs ($>98\%$ utilization—extremely high risk of pod scheduling failures!).
   - `/23` gives $512$ total, $507$ usable in AWS.
5. **Architectural Decision:** Allocate a **`/23`** subnet ($507$ usable IPs) to ensure safe operational headroom for auto-scaling and avoid cluster-wide IP exhaustion.

## 7. Hands-On CLI Subnet Math Verification

We can verify prefix math instantaneously via PowerShell or Bash:

### PowerShell Quick Subnet Calculator Function
```powershell
# Quick PowerShell calculation of total and AWS usable hosts
function Get-CidrCapacity ([int]$Prefix) {
    $total = [math]::Pow(2, (32 - $Prefix))
    $onprem = if ($Prefix -ge 31) { 0 } else { $total - 2 }
    $aws = if ($Prefix -ge 29) { "Invalid (< /28)" } else { $total - 5 }
    $gcp = if ($Prefix -ge 29) { "Invalid (< /29)" } else { $total - 4 }

    [PSCustomObject]@{
        Prefix       = "/$Prefix"
        TotalIPs     = $total
        OnPremUsable = $onprem
        AwsUsable    = $aws
        GcpUsable    = $gcp
    }
}

Get-CidrCapacity 24
Get-CidrCapacity 27
Get-CidrCapacity 28
```

### Linux Python One-Liner (Standard `ipaddress` module)
```bash
python3 -c "import ipaddress; net = ipaddress.ip_network('10.0.14.73/27', strict=False); print(f'Network: {net.network_address}\nBroadcast: {net.broadcast_address}\nFirst Usable: {net.network_address + 1}\nLast Usable: {net.broadcast_address - 1}\nTotal: {net.num_addresses}')"
```

## 8. Comprehensive Self-Assessment & Verified Solutions

1. **How many host bits are in a `/28` subnet?**  
   *Answer:* $32 - 28 = \mathbf{4}$ host bits.
2. **What is the total address count for a `/22` network?**  
   *Answer:* $2^{(32 - 22)} = 2^{10} = \mathbf{1,024}$ total IP addresses.
3. **What is the subnet mask for `/20`?**  
   *Answer:* 20 network bits = `11111111.11111111.11110000.00000000` = `255.255.240.0`.
4. **Why does AWS reserve 5 IP addresses per subnet instead of 2?**  
   *Answer:* AWS reserves `.0` (network), `.1` (VPC router), `.2` (AmazonProvidedDNS), `.3` (future use), and `.255` (broadcast).
5. **What is the minimum subnet size supported in an AWS VPC?**  
   *Answer:* `/28` (16 total addresses, 11 usable).
6. **How many usable IPs does a GCP `/24` subnet provide?**  
   *Answer:* $256 - 4 = \mathbf{252}$ usable addresses (GCP reserves `.0`, `.1`, `.254`, `.255`).
7. **Given `192.168.5.140 / 26`, what is the network address and broadcast address?**  
   *Answer:* `/26` has block size $256 - 192 = 64$. Multiples: `0, 64, 128, 192`. `140` falls between `128` and `192`.  
   - Network: `192.168.5.128`  
   - Broadcast: `192.168.5.191`
8. **What is the first and last usable host for `10.50.0.0/18` in traditional on-prem?**  
   *Answer:* Block size in 2nd octet ($18 - 16 = 2$ bits $\rightarrow$ mask 192 $\rightarrow$ block size 64). Multiples: `0, 64`.  
   - Network: `10.50.0.0`  
   - Broadcast: `10.50.63.255`  
   - First usable: `10.50.0.1`  
   - Last usable: `10.50.63.254`
9. **In Azure, which IP addresses are reserved for DNS mappings in `10.1.0.0/24`?**  
   *Answer:* `10.1.0.2` and `10.1.0.3`.
10. **Why can't you connect two VPCs with CIDR blocks `10.0.0.0/16` and `10.0.1.0/24` via VPC Peering?**  
    *Answer:* `10.0.1.0/24` is a subset of `10.0.0.0/16`. Overlapping CIDRs cannot be peered because router routing tables cannot unambiguously resolve which VPC owns the conflicting IP space.

## 9. Key Takeaways

- CIDR replaces obsolete classful networking with flexible bitmask prefixes (`/n`).
- The Magic Number shortcut ($\text{Block Size} = 256 - \text{mask octet}$) lets you identify subnet boundaries instantly.
- Traditional on-premises subnets lose **2** IPs ($2^h - 2$).
- AWS and Azure subnets lose **5** IPs ($2^h - 5$).
- GCP subnets lose **4** IPs ($2^h - 4$).
- AWS subnets cannot be smaller than `/28`.
- In production Kubernetes and container environments, always size subnets for peak auto-scaling and rolling update surge capacity to avoid pod IP exhaustion.
