# Day 145 – Terraform Locals & Dynamic Blocks

**Date:** 24 July 2026
**Duration:** ~3 Hours
**Focus:** HCL `locals`, `dynamic` blocks for nested resources, explicit dependencies (`depends_on`), and `lifecycle` safeguards.

---

## 🎯 Objective

Refactor Terraform code to be DRY (Don't Repeat Yourself) using locals and dynamic blocks, while enforcing production-grade safety mechanisms using lifecycle rules.

---

## ✅ What I Learned & Executed

### Local Values (`locals`)

Locals allow you to compute a value once and reuse it multiple times within a module. Unlike variables which are inputs provided by the user, locals are internal to the module.

```hcl
locals {
  common_tags = {
    Environment = var.environment
    ManagedBy = "Terraform"
  }
}
# Usage: tags = local.common_tags
```

---

### Dynamic Blocks

Certain AWS resources (like Security Groups) require nested blocks. You cannot use `count` or `for_each` directly on nested blocks. The `dynamic` block solves this by iterating over complex variables (like lists of ports) to generate nested configurations dynamically.

```hcl
dynamic "ingress" {
  for_each = var.allowed_ports
  content {
    from_port = ingress.value
    to_port = ingress.value
    protocol = "tcp"
    cidr_blocks = ["0.0.0.0/0"]
  }
}
```

---

### Explicit Dependencies (`depends_on`)

Terraform automatically builds a dependency graph based on resource references. However, when a resource depends on another but does not explicitly reference it in code (e.g. an EC2 instance needing an IAM role attachment to exist first), `depends_on` forces Terraform to wait.

```hcl
depends_on = [aws_iam_role_policy.this]
```

---

### Lifecycle: `prevent_destroy`

The ultimate safety net for stateful resources like RDS databases. When set to true, Terraform will throw a fatal error if a `terraform apply` or `terraform destroy` command attempts to delete the resource.

```hcl
lifecycle {
  prevent_destroy = true
}
```

---

### Lifecycle: `create_before_destroy`

By default, Terraform destroys an old resource before building its replacement. For zero-downtime deployments, setting this to true forces Terraform to provision the new infrastructure first, route traffic, and then tear down the old one.

```hcl
lifecycle {
  create_before_destroy = true
}
```

---

### Lifecycle: `ignore_changes`

Prevents Terraform from reverting manual changes made outside of the code. For example, if auto-scaling groups add tags dynamically, Terraform would normally try to remove them to match the code. This rule tells Terraform to ignore specific attributes during state comparison.

```hcl
lifecycle {
  ignore_changes = [tags]
}
```
