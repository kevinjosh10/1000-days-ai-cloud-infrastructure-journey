# Day 142 – Variables, Outputs & Data Sources

**Date:** 21 July 2026
**Duration:** ~3 Hours
**Focus:** Dynamic Infrastructure as Code, HCL Variable Typing, Exporting Outputs, Dynamic Resource Querying (Data Sources), and Complete EC2 Deployment

---

## 🎯 Objective

Eliminate hardcoded values from Terraform configuration files to build dynamic, reusable, and self-documenting Infrastructure as Code architectures.

Learn:

- The Anti-Pattern of Hardcoded Configurations
- Input Variables (`variable` block)
- Strict HCL Type Enforcement (`string`, `number`, `list`, `map`)
- Output Values (`output` block)
- Querying Existing Cloud State (`data` block)
- Dynamic Amazon Machine Image (AMI) Resolution
- Resource Interpolation (`${var.environment}`)

Practice:

- Executing The Anti-Pattern of Hardcoded Configurations in local `main.tf` files
- Executing Input Variables (`variable` block) in local `main.tf` files
- Executing Strict HCL Type Enforcement (`string`, `number`, `list`, `map`) in local `main.tf` files
- Executing Output Values (`output` block) in local `main.tf` files
- Executing Querying Existing Cloud State (`data` block) in local `main.tf` files
- Executing Dynamic Amazon Machine Image (AMI) Resolution in local `main.tf` files
- Executing Resource Interpolation (`${var.environment}`) in local `main.tf` files
- Building a dynamic Ubuntu EC2 instance utilizing variables
- Exporting the public IP address back to the terminal
- Binding Security Groups dynamically via HCL references
